SYSTEM CASE STUDY PUBLISHED COMPANY-WIDE ENTERPRISE ARCHITECTURE

SIRIS: Structured Intelligent Routing & Information System

A production, retrieval-augmented, multi-agent enterprise assistant giving one natural-language entry point to distributed architecture governance knowledge. Published company-wide across Federated Hermes.

Role Sole Architect & Developer
Timeline May - Aug 2026
Stack Copilot Studio · Azure OpenAI (GPT-5.5) · Entra ID
Verification 165+ Rubric Cases · 6/6 Specialists Verified
01 // CONTEXT

The Problem

Sitting in weekly Architecture Review Board meetings, specific technical questions kept stalling high-level discussions because architects and engineers didn't know which library owned the authoritative answer.

Governance knowledge was fragmented across six distinct SharePoint libraries - Standards, Principles, Exceptions, Permits to Build (PtBs), Roadmaps, and Production Position Documents (PPDs). Each had its own owners, taxonomy, and dense institutional vocabulary.

Finding a definitive answer meant knowing which repository owned it, locating the file, and cross-referencing multiple documents by hand. This reliance on scarce subject-matter experts introduced significant drag - and created a real risk that teams might skip required governance checks because the manual lookup path was too costly. The goal was simple: surface the authoritative source in seconds with complete verification.

02 // ARCHITECTURE

Multi-Agent Topology

SIRIS uses a two-level hub-and-spoke multi-agent topology. One ARB router receives the user’s query, analyzes intent, and delegates directly to one of six specialist agents. An eighth agent extends this exact pattern to Compliance as a proof of concept.

03 // DECISIONS

Engineering Tradeoffs

Six critical production challenges, root causes, and architectural fixes.

1. Connected-Agent Chaining Ceiling

Problem The original planned architecture had an Enterprise Router above the ARB Department Router (3-level hierarchy). Copilot Studio rejected this with the error "Cannot connect an agent that already has a connected agent." What I Did Re-architected the system from a 3-level tree into a 2-level hub-and-spoke. The ARB became its own top-level entry point, delivering the same user experience with reduced latency and no nesting overhead.

2. Attachment Delegation Boundary

Problem Document uploads for draft reviews (such as reviewing a draft architecture proposal or technical position paper) failed when attached to the router. Attachments did not cross the connected-agent delegation boundary in preview. What I Did Established an operational direct-specialist upload pattern. Users review draft documents directly within the relevant specialist agent, preserving complete assistive gap-analysis capabilities.

3. Dataverse Search-Index Quota Constraints

Problem Configuring large SharePoint document libraries as knowledge sources consumed shared environment Dataverse search-index quota (~255 of ~950 units consumed with Principles connected). What I Did Documented the index consumption pattern and carefully scoped knowledge source connections across the 6 libraries to ensure high-priority certified standards remained fully indexed without exhausting shared tenant capacity.

4. Separation of Routing vs. Response Formatting

Problem Adding brevity and formatting rules into the Router’s instructions degraded generative orchestration, causing missing routing labels, {"Done":true} JSON leaks, and response duplication. What I Did Strictly stripped all formatting, length, and label generation rules from the router. The router contains only intent determination and routing logic. All formatting rules were pushed into the specialist agents.

5. Authoring Canvas Duplicate Responses

Problem During development, agents intermittently printed identical correct responses 2 - 4 times in a single turn within the Copilot Studio test panel. What I Did Systematically investigated 8+ candidate causes (stray router knowledge, conversational boosting, fallback topics, duplicate agent entries). Isolated the symptom to the preview test canvas and confirmed 0 production duplication defects in the company-wide deployment.

6. Systematic Configuration Defect Elimination

Problem Model verbosity, missing routing labels, {Bot.Name} resolving to the technical agent name instead of the branded system identity, and meta-comment leaks ("I cannot add to the prior response"). What I Did Moved a strict 50-word / 3-bullet length policy to the first line of each specialist prompt (exploiting positional prompt weighting), baked routing labels into specialist first lines, replaced dynamic variables with static greetings, and suppressed model self-narration.
04 // VERIFICATION

Evaluation Portfolio

165+ rubric-based test cases separating production engineering from prototype demos.

To verify system reliability before rolling it out organization-wide, I authored and maintained 165+ test cases across 5 CSV evaluation suites.

Master ARB Suite

100 test cases: 12 per specialist across all six domains, plus multi-specialist fan-out, out-of-scope refusals, and Entra ID access boundaries.

Compliance PoC Suite

20 test cases: achieved a clean 20/20 run across advertising material classification, active-dated disclosure matching, and compliance language checks.

Critical Evaluation Insight: Custom Rubric vs. Automated Grader

The platform's built-in grader scored generic conversational quality rather than governance accuracy - failing correct refusals because it interpreted a refusal as "did not answer." As a result, I conducted rigorous manual verification across all test runs using a customized rubric evaluating grounding, citation presence, and status discrimination.

05 // PERSPECTIVE

Key Takeaways

"AI is a grounding problem before it's a model problem. Grounding, citations, permission scoping, and refusal behavior are core architectural decisions, not afterthoughts."

The project demonstrated that reliable enterprise AI does not come from clever general-purpose prompting; it requires strictly bounding where each agent can look, ensuring the user's existing security credentials govern retrieval, and engineering deterministic refusal states.
