01 // MOTIVATION

Design Target

Why stack-based bytecode architectures matter for portable, memory-safe execution.

The C0 language - a strongly-typed, memory-safe C derivative developed at Carnegie Mellon University - bridges the expressive power of systems programming with the safety guarantees of runtime bounds validation and automatic garbage collection.

The objective of StackScope was to construct a production-grade execution runtime from first principles in ANSI C99: a bytecode loader, an efficient fetch-decode-execute dispatch engine, structured activation call records, manual memory management with bounds checking on dynamic allocations, and deterministic trap recovery - all while maintaining an executable footprint under 100 KB and achieving over 500 million instructions per second.

02 // MEMORY MODEL

Memory Layout

Zero padding bloat and explicit bounds validation on all dynamic allocations.

Every internal data structure is optimized for cache alignment and minimal memory overhead: 

/* 1. Value Container: 16 bytes */
typedef struct {
    c0_type type;       /* 4 bytes (enum: C0_INT or C0_PTR) */
    /* 4 bytes implicit alignment padding */
    union {
        int32_t i;      /* 4 bytes signed integer */
        void   *p;      /* 8 bytes 64-bit generic pointer */
    } val;              /* 8 bytes */
} c0_value;             /* Total: 16 bytes */

/* 2. Activation Record: 56 bytes per call frame */
typedef struct frame_s {
    const uint8_t *P;   /* 8 bytes: Bytecode array pointer */
    size_t         pc;  /* 8 bytes: 16-bit Program counter */
    c0_value      *V;   /* 8 bytes: Local variables array */
    c0_value      *S;   /* 8 bytes: Operand evaluation stack */
    size_t         sp;  /* 8 bytes: Stack pointer index */
    size_t num_vars;    /* 8 bytes: Allocated local variable slots */
    size_t code_len;    /* 8 bytes: Bytecode length boundary */
} frame;                /* Total: 56 bytes */

/* 3. Dynamic Array Header: 16 bytes */
typedef struct {
    int   count;        /* 4 bytes: Number of elements */
    int   elt_size;     /* 4 bytes: Size in bytes per element */
    void *data;         /* 8 bytes: Pointer to heap payload */
} c0_array;             /* Total: 16 bytes */
Memory Safety Invariants

1. Stack-Allocation Overhead: An execution call stack depth of 1,000 recursive invocations consumes only ~56 KB of activation record metadata.
2. Dynamic Heap Safety: Arrays store metadata explicitly (c0_array). Every index access checks 0 ≤ i < count. Out-of-bounds accesses trigger an immediate graceful trap via setjmp/longjmp, guaranteeing 0 unhandled segmentation faults.

04 // DISPATCH

Dispatch Tradeoffs

Empirical comparison: Standard C switch vs. GCC computed-goto threaded dispatch.

The runtime implements dual dispatch strategies toggled via -DUSE_COMPUTED_GOTO: standard C switch table vs. GCC &&label direct threaded dispatch.

Workload Switch Dispatch Computed-Goto Switch MIPS Goto MIPS Delta
Arithmetic Loop (1M) 26.94 ms 35.40 ms 556.8 MIPS 423.7 MIPS Switch +31.4% faster
Collatz Table (1..20) 5.02 ms 4.80 ms 1.11 MIPS 1.16 MIPS Computed-Goto +4.6% faster
Prime Sieve (≤ 50) 4.94 ms 4.77 ms 652.4 KIPS 675.7 KIPS Computed-Goto +3.6% faster
Recursive Factorial (12!) 5.20 ms 5.09 ms 218.1 KIPS 222.8 KIPS Computed-Goto +2.2% faster
Architectural Insight: On x86-64 with deep branch prediction pipelines (BHT/BTB), a dense switch jump table localized in the L1 instruction cache outperforms threaded dispatch on tight loops with low instruction diversity. On irregular, branch-heavy workloads with higher instruction diversity (Collatz, primes), computed-goto's dedicated indirect jump site per opcode reduces BTB pollution and provides a 2 - 5% speedup.
05 // RESILIENCE

Fault Traps

12 distinct runtime error classes caught gracefully with zero unhandled segmentation faults.

In classical C interpreters, invalid memory dereferences or arithmetic overflows cause fatal segmentation faults that crash the entire host process. StackScope wraps the VM dispatch loop in a setjmp/longjmp fault envelope (defined in include/c0vm_abort.h): 

#define c0_abort(msg) do { \
    c0vm_last_error = (msg); \
    longjmp(c0vm_abort_env, 1); \
} while(0)
12 Architectural Trap Classes Handled:

1. Division by zero (IDIV, IREM)
2. Two's-complement arithmetic overflow (INT_MIN / -1)
3. Array index out of bounds ($i < 0$ or $i \ge \text{count}$)
4. Array allocation with negative length ($n < 0$)
5. Null pointer dereferences on structs and arrays
6. Call stack overflow on unbounded recursion
7. Shift count out of bounds ($k < 0$ or $k \ge 32$)
8. Invalid opcode in bytecode stream
9. Truncated bytecode buffer read
10. Native function dispatch index out of bounds
11. Operand stack underflow on binary operations
12. Memory allocation failure on heap exhaustion
